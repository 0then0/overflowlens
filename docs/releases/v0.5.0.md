# OverflowLens v0.5.0

Adds a route slow-share mode: exact bounds on the share of requests of one `http.route` that took longer than a chosen duration, after SDK cardinality overflow, from one delta `http.server.request.duration` histogram. All existing modes and their v1 to v4 reports are unchanged; reports now record application version 0.5.0.

## Changes

- New mode **HTTP route slow share (delta)**. Overflow loses `http.route` but keeps its bucket counts, so its observations are split into fast (`F`) and slow (`S`) at an exact explicit bucket boundary, chosen in seconds. The share of the route lies between `E / (K + F)` and `(E + S) / (K + S)`; other routes never enter the denominator and overflow is not attributed to the route. Slow means strictly longer; an observation exactly on the boundary is fast.
- With no known request of the route (`K = 0`) no share, bound or verdict is reported, because the data cannot show that the route had requests.
- Refuses a missing or invalid `http.route` on any non-empty ordinary point, absent bucket counts, a boundary that is not an exact bound, a unit other than `s` and non-delta input. Values are never interpolated or rounded.
- Report schema v5 records the route, threshold in seconds, counts, exact fractions, witnesses and an explanation of the unknown attribution.
- Validated with a real OpenTelemetry Go SDK v1.47.0 Histogram receiving known durations through the Metric API, with a small cardinality limit, a no-overflow control and a case without observations of the route: `npm run validate:http-route`. This validates SDK aggregation; it is not a measurement of real HTTP latency.

## Download and run

Download `overflowlens-0.5.0.zip` from [GitHub Releases](https://github.com/0then0/overflowlens/releases), extract it, and change into `overflowlens-0.5.0`. Start a local HTTP server:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. Node.js, Go and Docker are not needed to use the archive. Use HTTPS for remote hosting; `file://` is unsupported. `SHA256SUMS.txt` contains the archive checksum.

## Scope and compatibility

Not supported: cumulative latency windows, exponential histograms, quantiles, interpolation within buckets, arbitrary attribute filters and live ingestion. Data lost before the export cannot be detected. See the [input contract](https://github.com/0then0/overflowlens/blob/v0.5.0/docs/input-contract.md). The Pages site stays at its separately recorded version until redeployed.
