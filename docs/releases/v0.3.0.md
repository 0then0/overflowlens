# OverflowLens v0.3.0

Adds an HTTP 5xx mode: exact bounds on the share of HTTP 5xx responses after SDK cardinality overflow, from a delta `http.server.request.duration` histogram. The delta and cumulative Sum modes, their mathematics and their v1 and v2 reports are unchanged; reports now record application version 0.3.0.

## Changes

- New mode **HTTP 5xx histogram (delta)**. The `count` of each datapoint is the number of completed requests. Ordinary points are classified by integer `http.response.status_code` (500–599 is 5xx, 100–499 other). A missing, invalid or contradictory status refuses the calculation. The SDK overflow point keeps the strict single-attribute rule. Bounds are `E/T` and `(E+O)/T` with exact BigInt arithmetic, including uint64 counts above `Number.MAX_SAFE_INTEGER`.
- Strict OTLP `HistogramDataPoint` validation: time bounds, flags, types, bucket and bound consistency. One corrupt point blocks the selected stream.
- The confirmation states that each observation is one completed request, ordinary points keep a correct status, and downstream processing changed neither counts nor attribution. A matching metric name never confirms this.
- Report schema v3 records the input metric, classification criterion, source SHA-256, interval, confirmed conditions and exact results.
- Validated against real OpenTelemetry Go `otelhttp` v0.72.0 exports (SDK v1.47.0, delta, default explicit histogram aggregation) with a small cardinality limit: `npm run validate:http`.

## Download and run

Download `overflowlens-0.3.0.zip` from [GitHub Releases](https://github.com/0then0/overflowlens/releases), extract it, and change into `overflowlens-0.3.0`. Start a local HTTP server:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. Node.js, Go and Docker are not needed to use the archive. Use HTTPS for remote hosting; `file://` is unsupported. `SHA256SUMS.txt` contains the archive checksum.

## Scope and compatibility

Not supported in the new mode: cumulative and exponential histograms, latency analysis, route grouping and Collector pipeline changes. Provenance assumptions are as in [v0.2.0](https://github.com/0then0/overflowlens/blob/v0.3.0/docs/releases/v0.2.0.md); see the [input contract](https://github.com/0then0/overflowlens/blob/v0.3.0/docs/input-contract.md). The Pages site stays at its separately recorded version until redeployed.
