# OverflowLens v0.4.0

Adds a cumulative HTTP 5xx window: exact bounds on the share of HTTP 5xx responses between two cumulative `http.server.request.duration` exports, after SDK cardinality overflow. Cumulative is the default of Go SDKs and the standard OTLP exporter. The Sum modes, the delta HTTP mode and their v1, v2 and v3 reports are unchanged; reports now record application version 0.4.0.

## Changes

- New mode **HTTP 5xx histogram (cumulative window)**. Per-series `count` increments are computed with BigInt, classified by `http.response.status_code` (500-599 is 5xx) and fed to the same exact `E/T` .. `(E+O)/T` bounds. Baseline observations are excluded.
- The pair must have identical Resource, scope and metric definition, ordered boundaries, the same series (nothing is zero-filled), unchanged known start times, nondecreasing counts and an unchanged bucket layout. New or missing series, unknown starts, resets and SDK restarts are refused. One corrupt histogram point blocks the pair. Buckets, `sum`, `min` and `max` never estimate latency.
- The interface shows the exact window, every pair check, and the known requests, known 5xx and overflow of the window. A threshold change reuses the prepared counts; a change of file, stream or boundary clears the confirmation and result.
- Report schema v4 records both source hashes, selected identities, boundaries, source and final counts, increments, classification, applicability conditions and exact bounds.
- Validated against real OpenTelemetry Go `otelhttp` v0.72.0 exports (SDK v1.47.0, default cumulative temporality, cardinality limit 8), with a restart refusal and a zero window: `npm run validate:http-cumulative`.

## Download and run

Download `overflowlens-0.4.0.zip` from [GitHub Releases](https://github.com/0then0/overflowlens/releases), extract it, and change into `overflowlens-0.4.0`. Start a local HTTP server:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. Node.js, Go and Docker are not needed to use the archive. Use HTTPS for remote hosting; `file://` is unsupported. `SHA256SUMS.txt` contains the archive checksum.

## Scope and compatibility

Not supported: exponential histograms, window recovery across resets, process aggregation, route grouping and live ingestion. Provenance assumptions are as in [v0.3.0](https://github.com/0then0/overflowlens/blob/v0.4.0/docs/releases/v0.3.0.md); see the [input contract](https://github.com/0then0/overflowlens/blob/v0.4.0/docs/input-contract.md). The Pages site stays at its separately recorded version until redeployed.
