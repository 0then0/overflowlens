# OverflowLens v0.1.0

The first public release of OverflowLens, a local browser application for exact error-rate bounds after OpenTelemetry SDK cardinality overflow.

## Included

- Import OTLP JSON metrics without uploading files to a server.
- Select one Resource/scope/metric stream and one complete collection interval.
- Calculate exact lower and upper error-rate bounds with `BigInt` arithmetic.
- Compare the bounds with a percentage limit, including equality.
- Export an explanatory JSON report with exact counts, fractions, settings, assumptions and source SHA-256.
- Detect duplicate measurement identities, conflicting definitions, malformed related containers and ambiguous overflow tagging.
- Normalize equivalent base64 attributes and finite quoted double attributes without losing integer precision.
- Reproduce real Go OpenTelemetry SDK v1.47.0 exports and their independently recorded ground truth.

## Download and run

Download `overflowlens-0.1.0.zip`, extract it and change into the `overflowlens-0.1.0` directory. Serve it with any static HTTP server, for example:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. The archive contains the application, Worker, examples, license, third-party notices and launch instructions. Node.js and Go are not required to use the compiled application. Opening `index.html` through `file://` is unsupported.

`SHA256SUMS.txt` contains the archive checksum. GitHub also provides source archives for the release tag. See the [README](https://github.com/0then0/overflowlens/blob/v0.1.0/README.md) for development setup.

## Scope and limitations

The supported model is a synchronous request counter represented as a monotonic integer delta Sum, with a boolean outcome on every ordinary point and an SDK overflow point containing only `otel.metric.overflow=true`. Input files are limited to 5 MiB. Completeness, SDK provenance and absence of downstream transformations require user confirmation.

This release analyzes one imported interval. It does not verify a full SLO, recover lost outcomes or support cumulative sums, floating-point counts, histograms or Collector tagging with additional measurement attributes. SDK validation covers Go v1.47.0; browser acceptance checks cover Chromium.

Validation covers exact arithmetic, input refusals, official SDK fixtures, local browser import and report export. The release workflow checks formatting, lint, unit/SDK fixture tests and the production build before publishing.
