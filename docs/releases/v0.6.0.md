# OverflowLens v0.6.0

Extends the route slow-share mode to delta `ExponentialHistogram` exports of `http.server.request.duration`. Explicit-bucket route analysis, all other modes and report schemas v1 to v5 are unchanged; reports now record application version 0.6.0.

## Changes

- The route slow-share mode accepts a delta `ExponentialHistogram` with unit `s`. The duration threshold is typed in seconds and compared as an exact decimal; slow means strictly longer.
- Each bucket, with its own point's `scale` and `offset`, is certainly fast, certainly slow or uncertain when its range contains the threshold or floating-point error could change the comparison. The zero bucket follows `zeroThreshold`. A threshold inside a bucket leaves a range even without overflow.
- With `L` and `U` the certainly and possibly slow known requests of the route and `F_max`, `S_max` the possibly fast and possibly slow overflow observations, the share lies between `L / (K + F_max)` and `(U + S_max) / (K + S_max)`. The interface shows how many observations are uncertain because of threshold crossing and because of route loss.
- Refuses non-empty negative buckets, scales outside −10 to 20, invalid bucket indexes, inconsistent counts and thresholds below 2^−1022. Sum, min, max and exemplars never narrow the range.
- Report schema v6 records the threshold, `L`, `U`, `F_max`, `S_max`, both witnesses and the scale, buckets and classification of every relevant point, so the bounds can be replayed from the report.
- Validated with real OpenTelemetry Go SDK v1.47.0 exponential histograms with known durations, a small cardinality limit, a no-overflow control and a case without observations of the route; every exported bucket is checked against an exact placement of the recorded values: `npm run validate:http-route-exponential`. This validates SDK aggregation; it is not a measurement of real HTTP latency.

## Download and run

Download `overflowlens-0.6.0.zip` from [GitHub Releases](https://github.com/0then0/overflowlens/releases), extract it, and change into `overflowlens-0.6.0`. Start a local HTTP server:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. Node.js, Go and Docker are not needed to use the archive. Use HTTPS for remote hosting; `file://` is unsupported. `SHA256SUMS.txt` contains the archive checksum.

## Scope and compatibility

Not supported: cumulative latency windows, merging intervals, quantiles, interpolation within buckets and live ingestion. Data lost before the export cannot be detected. See the [input contract](https://github.com/0then0/overflowlens/blob/v0.6.0/docs/input-contract.md). The Pages site stays at its separately recorded version until redeployed.
