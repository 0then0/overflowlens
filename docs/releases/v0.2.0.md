# OverflowLens v0.2.0

Analyze exact error-rate bounds between two cumulative OpenTelemetry request-counter snapshots. Delta interval analysis remains available in the same local browser application.

## Changes

- Choose Delta interval or Cumulative window, with separate Before and After imports for cumulative mode.
- Select matching streams and collection boundaries, inspect structural applicability, and confirm provenance before obtaining a verdict.
- Calculate exact per-point increments with BigInt, excluding all baseline observations.
- Refuse changed starts, decreasing individual points, missing counterparts, mismatched definitions, invalid flags and inconsistent collection timestamps.
- Reuse validated increments and totals when only the threshold or provenance confirmation changes.
- Clear confirmation and the previous verdict when files, streams, boundaries, outcome or mode change; ignore replaced imports and stale Worker responses.
- Export cumulative schema v2 with both original-byte SHA-256 hashes, selected identities, exact window, assumptions, applicability checks, per-point before/after counts and increments, exact fractions and endpoint witnesses.
- Preserve delta report schema v1 and field names. Hashes identify original file bytes, including an optional UTF-8 BOM.
- Validate cumulative windows with the official Go SDK v1.47.0 default ManualReader, OTLP HTTP exporter and ProtoJSON serializer.

## Download and run

Download `overflowlens-0.2.0.zip` from [GitHub Releases](https://github.com/0then0/overflowlens/releases), extract it, and change into `overflowlens-0.2.0`. Start a local HTTP server:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Open http://127.0.0.1:8080. The application, Worker and assets are in this directory; there is no nested `dist/`. Node.js and Go are not needed to use the archive. Use HTTPS for remote hosting; `file://` is unsupported. `SHA256SUMS.txt` contains the archive checksum.

For source setup, see the [README](https://github.com/0then0/overflowlens/blob/v0.2.0/README.md). Source builds write files into `dist/`; serve that directory when running a source build.

## Scope and compatibility

Each selected cumulative stream must have exactly one collection timestamp per file, identical measurement identities on both sides, known unchanged starts for every corresponding series, and nondecreasing counts. Different series may have different starts. New or missing series, unknown starts, resets and multiple collection timestamps in one selected cumulative export are unsupported.

Completeness, synchronous request-count meaning, one boolean outcome per request, continuous source history, stable SDK attribution and unchanged downstream counts/attributes remain user-confirmed assumptions. Hashes do not prove authenticity; exemplars do not recover all overflow outcomes.

The SDK workload starts with baseline total 112, including overflow 5. Its 1,000-request window produces `K=901, E=1, O=99, T=1000`, bounds 0.1%…10%, containing the independent truth `34/1000`. A View preserving only the outcome gives exact rate 3.4%. Real zero-increment collections produce NO_DATA, and exports from a restarted provider are refused for changed starts.

See [SDK validation](https://github.com/0then0/overflowlens/blob/v0.2.0/docs/validation.md) for reproduction and synthetic refusal controls. Validation covers the pinned Go SDK and Chromium; it does not establish universal cross-SDK compatibility or export completeness.
